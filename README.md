# Команда для 3D-печатных товаров: начало реализации

Это начальная локальная реализация ТЗ v2. Первой площадкой выбран Ozon; существующих карточек и продаж нет. Интеграции с аккаунтами, сервер, база, Telegram, независимый ревизор и шлюз записи пока не настроены и не работают автоматически.

## Что уже есть

- `gateway/` — прототип FastAPI-шлюза: журнал, режим только чтение и аварийная остановка. Пока любая запись в Ozon отклоняется; модуль ограничений не подключён к действующим API.
- `gates/` и `bot/` — серверный реестр подтверждений владельца и Telegram long-polling. Решения связаны с версией товара; реальный Telegram и VPS ещё не настроены.

- `calc/` — детерминированный расчёт себестоимости, прибыли, минимальной цены, порогов и стресс-сценария. Значения задаются явно; доли указываются как числа от 0 до 1. `examples/` содержит условный контрольный пример ТЗ, а не данные бизнеса. Результат не подтверждает спрос или право продажи.
- `scout/` — локальный импорт ссылки и паспорта кандидата; автоматический поиск этим модулем не выполняется.
- `demand/` — оценка спроса по пяти критериям при наличии обоснованных оценок и источников, с сохранением в базу.
- `reports/` и `daily/` — локальная сводка и её подготовка по расписанию; шаблоны systemd пока не установлены и в Telegram не отправляют.
- `products/` — сохранённые паспорта найденных моделей; включён первый кандидат с подтверждёнными ссылками и отмеченными пробелами.
- `pipeline/` — локальная проверка сведений для перехода по стадиям, включая три решения владельца и отметку о правах. `blockers(candidate)` возвращает список недостающих условий, `advance(candidate)` возвращает копию со следующей стадией. Это прототип: он не удостоверяет подлинность подтверждений, ссылок, оценки калькулятора или ревизии, не подключён к Telegram и не обеспечивает защиту внешних действий. Перед подключением записи потребуется отдельный защищённый шлюз из ТЗ.
- `AGENTS.md` и `roles/` — рабочие инструкции для восьми ролей, но не работающие агенты или расписания. Изображения карточек команда готовит сама по референсам источника модели и найденным материалам с применением ИИ; сгенерированные изображения не являются доказательством фактического вида физического образца.
- `config/production.yaml` — данные владельца: Ozon и цены PLA и PETG по 1 000 ₽/кг; остальные параметры пока не заполнены. `config/production.example.yaml` — шаблон. С `--material PLA` или `--material PETG` калькулятор берёт цену из этого файла и указывает её источник; остальные исходные данные вводятся явно.
- `production/` — предложения по первой партии, точке заказа и распределению мощности; запуск печати не автоматизирован.
- `deploy/` — неустановленный шаблон VPS pull-CD с проверкой тестов и переключением релиза; см. ограничения в `deploy/README.md`.
- `.github/workflows/ci.yml` — проверки кода и тестов на GitHub без секретов маркетплейсов.
- `workcycle/` — локальный цикл проверки кандидата: выбор цены материала, расчёт, список блокировок и сохранение результата; подробности в `workcycle/README.md`.
- `storage/` — локальная база SQLite с историей кандидатов и расчетов; это прототип, не развёрнутая база PostgreSQL.
- `collectors/ozon.py` — проверочный сбор одной страницы списка товаров Ozon; полная выгрузка и работа с реальным кабинетом ещё не проверены.
- `operations/readiness.py` — локальная проверка готовности и недостающих данных; `systemd/` содержит неустановленные шаблоны ежедневной проверки, которые не запускают агентов.
- `marketplace_check.py` — ранее созданная проверка доступа к API, описана ниже.

Контрольный пример можно запустить командой:

```bash
python3 -m calc < examples/spec_7_3.json
```

Условный пример локального цикла (путь к новой базе можно заменить):

```bash
python3 -m workcycle --db /tmp/wbandozon-demo.sqlite3 < examples/workcycle_demo.json
```

Пример намеренно не проходит пороги и завершится с кодом 2; все входы, кроме заданной владельцем цены PLA, условные. Реальные товары он не ищет.

Проверить наличие исходных данных без сети: `python3 -m operations.readiness`.

Установка закреплённых зависимостей и проверка без токенов:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest -v
```

Установка пакетов требует доступа к PyPI; сами тесты не используют реальные токены и не вызывают внешние сервисы.

Все параметры расчёта обязательны; поля и доступные пороги перечислены в `calc/economics.py`. Пороги из ТЗ — стартовые ориентиры и могут быть переопределены в объекте `limits` JSON; общий `config/limits.yaml` пока не подключён. Для реального решения нужны данные своего производства, актуальные тарифы конкретной площадки и подтверждённая бухгалтером ставка налога. Отсутствующий в приложении регламент v1 и исходные данные его контрольного расчёта ещё нужны для полной проверки требований.

## Дальнейшие шаги

Подготовить данные о принтерах, материалах, упаковке и налоговом режиме, затем настроить доступ к Ozon только для чтения и проверить его. До работы с VPS в ТЗ отдельно предписана смена ранее раскрытого root-пароля. Секреты в чат и репозиторий не передаются. Публикация и изменения в кабинетах потребуют реализации и проверки шлюза, а также решений владельца.

# Безопасное подключение API маркетплейсов

Здесь подготовлена проверка доступа к API Wildberries и Ozon. Пароли от личных кабинетов, коды подтверждения и доступ к кабинету ей не нужны. Ключи ещё не настроены; фактический доступ зависит от выданных ключам прав и должен быть проверен отдельно.

## Ключи

Создайте отдельный API-ключ для каждого кабинета и выдайте ему только права на чтение, нужные для работы. Для Wildberries предусмотрен запрос проверки соединения; для Ozon — чтение списка товаров с ограничением одним товаром. Выбирайте соответствующие доступные категории прав при создании ключа. Если для нужной операции нельзя ограничить права только чтением, прежде оцените фактически выдаваемые права. Дополнительные операции и права можно добавить позже, когда будут понятны задачи.

Храните ключи маркетплейсов только в защищённых настройках на VPS, как предусмотрено ТЗ, а не в GitHub Actions, чате, репозитории, коде, аргументах команд или скриншотах. Привяжите имена переменных:

* `WB_API_TOKEN` — API-токен Wildberries.
* `OZON_CLIENT_ID` — Client ID кабинета Ozon.
* `OZON_API_KEY` — API-ключ Ozon.

Секреты, доступные процессу, потенциально доступны и другому коду с аналогичными правами в среде; ограничение доступа к среде и её настройкам остаётся важным. `.gitignore` снижает вероятность случайной публикации файлов с секретами, но не является хранилищем секретов. Если ключ попал в чат или другое неподходящее место, отзовите его в кабинете и создайте новый.

## Проверка

Когда секреты будут настроены в среде, выполните:

```bash
python3 marketplace_check.py wb
python3 marketplace_check.py ozon
```

Скрипт выводит только результат или код HTTP, не выводит ответ API, ключи или сведения о товарах. Он обращается только к фиксированным адресам, отклоняет перенаправления и использует стандартную проверку TLS Python; системные настройки прокси при этом сохраняются. Прокси среды может проверять HTTPS-трафик с помощью своего доверенного сертификата: это означает, что ему доступны данные запроса. На стороне маркетплейсов разрешения ключей являются основным ограничением. Эти меры уменьшают риск, но не гарантируют отсутствие утечек.

Проверка тестов в подготовленном окружении без секретов и сети: `.venv/bin/python -m unittest`.

Официальная документация: [Wildberries API](https://dev.wildberries.ru/openapi/api-information), [Ozon Seller API](https://docs.ozon.ru/api/seller/).
