# Неактивный пример ежедневной проверки

Сервис и таймер — шаблоны для пользовательского systemd на VPS. Их никто не устанавливал и не запускал. Сервис проверяет только локальное наличие указанных сведений и переменных в **своём процессе**, без сетевых вызовов и без публикации или записи в кабинеты. Это не планировщик агентов, не сборщик Ozon и не подтверждение доступа к API. Результат отправляется в журнал systemd, значения секретов туда не выводятся.

Для применения администратору сначала нужно подготовить VPS по разделу 12 ТЗ, разместить проект на сервере, поменять `WorkingDirectory` на абсолютный путь к нему и проверить Python. Затем можно самостоятельно скопировать оба файла в `~/.config/systemd/user/`, выполнить `systemctl --user daemon-reload`, проверить сервис `systemctl --user start wbandozon-readiness.service`, а после проверки включить таймер командой `systemctl --user enable --now wbandozon-readiness.timer`. Работу и ошибки показывает `journalctl --user -u wbandozon-readiness.service`. Для работы пользовательского таймера при отсутствии входа в систему может потребоваться отдельная настройка systemd администратором.

Переменные интерактивной оболочки не обязательно присутствуют в пользовательском сервисе. Поэтому отсутствие доступа в отчёте таймера означает только, что значения недоступны **этому процессу**. Не помещайте ключи в unit-файлы или журналы; способ безопасной передачи секретов будущим сервисам должен быть настроен отдельно.
