# Независимая проверка возвратов Ozon и повтора 429

Дата: 17 ноября 2026 года. Проверено локальное рабочее дерево ветки
`codex/ozon-finance-partial-20261117` после commit
`d43913d2090a7841c9246d3b5d6b810c898ead3a`, с незакоммиченными изменениями.
Хеши фиксируют байты этого дерева, а не будущего коммита или сервера.

## Проверки

На Windows, с фиктивными данными и без запросов к Ozon, выполнена команда из
`services/email-auth`:

```powershell
$python = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $python -B -m unittest -q test_health test_ozon_return_events test_ozon_finance_reports test_ozon_posting_candidates test_ozon_article_summary test_ozon_posting_status test_finance_gate test_ozon_details test_ozon_mcp test_external_mcp test_external_mcp_integration test_ozon_response_guard test_provider_payload.ProviderPayloadTests test_provider_deadline
```

Результат: **180 тестов, OK**. Отдельно три одноразовые программы через stdin
выполнили **9, 5 и 1 синтетическую проверку**; исходные программы не сохранены.
Первый набор относился к черновику, второй — к версии после исправления
замечаний. Проверялись повтор короткого 429, второй 429 с продлением cooldown,
неизвестный и длинный интервал, нехватка времени, HTTP-date без Date,
совпадение интервала с фиктивным ключом, конкурентное продление cooldown,
timeout с неизвестным исходом, фильтр чужого артикула, общий deadline,
отсутствие повтора составной сводки, невозможность выдать неверную дату и
неизвестное количество как ноль. В отдельном процессе `os._exit` во время
ожидания оставил cooldown в общем gate; новый вызов был заблокирован. Отдельный повтор после финальной правки подтвердил, что позднее пробуждение возвращает исходный 429 без повторного запроса и вывода тела ошибки.

Самостоятельно просмотрены описание MCP, включение файла в Dockerfile и
`.dockerignore`, а также связка worker и gate. `git diff --check` прошёл;
Git вывел предупреждения о переводах строк. `test_release` не выполнялся:
он импортирует `fcntl`, отсутствующий в Windows; проверку Linux это не
заменяет.

## Результат и границы

- Повтор выполняется максимум один раз для одиночного чтения после известного
  HTTP 429 с допустимым интервалом, сохранения cooldown и повторного входа в
  тот же gate. Ожидание не удерживает lock; другой процесс может продлить
  cooldown. Неизвестные интервалы и исходы, длинное ожидание и составная
  `ozon_article_summary` автоматически не повторяются. После второго 429
  новое ограничение сохраняется; третьего вызова нет. Ограничение действует
  только для процессов, использующих этот общий каталог gate.
- Возвраты выдаются одной страницей для одной схемы FBO или FBS; артикул и
  `logistic.return_date` повторно проверяются локально по UTC. В ответе
  отдельно указаны тип и текущий статус, исключённые строки, непроверенная
  полнота и неизвестный финансовый итог. Количество — сумма наблюдённых
  полей строк страницы с явными признаками неподтверждённой аддитивности и
  полноты; это не число завершённых возвратов денег.
- Во время ревизии исполнитель исправил два замечания: неправильные
  дополнительные даты статуса больше не выдаются как корректные даты;
  сумма количеств явно названа наблюдаемой суммой строк и снабжена признаками
  неподтверждённой аддитивности и полноты. Изменения покрыты локальными
  синтетическими проверками.
- `next_last_id_candidate` берётся из последней строки сырой страницы,
  включая строки, не прошедшие локальный фильтр. `page_return_ids` также
  относятся ко всей сырой странице и нужны для обнаружения повторов; их
  нельзя считать выбранными возвратами. Терминальная граница, согласованность
  страниц и полнота результатов у Ozon независимо не подтверждены. Пустая
  выбранная страница не доказывает отсутствие событий за период.
- Дата поля `logistic.return_date` не доказана как дата заказа, выкупа,
  окончательного возврата или денежной выплаты. Возвраты из одной недели
  нельзя автоматически вычитать из заказов той же недели. Доступен запрос
  периода до 90 календарных дней; адреса и причины покупателя в проекцию не
  включены.

Со слов исполнителя, реальные запросы `/v1/returns/list` для обеих схем и
позднейший одиночный `/accrual/postings` вернули HTTP 200. Он сообщает также
об ограниченном многостраничном проходе FBO без повторов ID: это не доказывает
полноту периода. Повторный вызов отдельного метода дневной реализации, по
сообщению исполнителя, вернул 403 с сообщением Ozon о Premium Plus. Я не
проверял эти запросы, кабинет, подписку, развёртывание или Claude.
Независимая проверка многостраничного обхода, корректная
интерпретация всех статусов и полнота финансового отчёта остаются
неподтверждёнными. Linux, Docker и GitHub Actions независимо не запускались;
разрешения на публикацию или вывод о полной приёмке этот отчёт не создаёт.
