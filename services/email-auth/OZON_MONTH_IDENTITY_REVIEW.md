# Независимая локальная проверка идентичности Ozon

Дата: 17 ноября 2026 года. Проверено рабочее дерево ветки
`codex/ozon-finance-partial-20261117` с исходным HEAD
`ebd651e963c95f7c796ff1439bb7498160adfd43` и незакоммиченными изменениями.
Использованы только вымышленные данные и подставные страницы; реальные API,
учётные данные и сервер не использовались. Хеши ниже относятся к локальным
байтам, а не к будущему коммиту или развёртыванию.

## Проверки

На Windows из каталога `services/email-auth` выполнена команда:

```powershell
$python = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $python -B -m unittest -q test_health test_ozon_synthetic_accrual test_ozon_return_events test_ozon_finance_reports test_ozon_posting_candidates test_ozon_article_summary test_ozon_posting_status test_finance_gate test_ozon_details test_ozon_mcp test_external_mcp test_external_mcp_integration test_ozon_response_guard test_provider_payload.ProviderPayloadTests test_provider_deadline
```

Результат: **213 тестов, OK**. Дополнительно отдельная одноразовая программа
через stdin выполнила **15 независимых синтетических проверок, OK**; программа
не сохранена в репозитории. Среди сценариев — перестановки конфликтующих
строк, пропуск идентичности в чужой строке, точный SKU больше 2^53, повтор
одной пары, лимит диагностики, отсутствие фиктивного ключа в ошибке, разрыв и
смешение синтетических страниц, изменение исходных данных после копирования,
истечение срока во время разбора, недопустимые часы, повтор ID, неизменность
снимка ошибки и одновременные вызовы.

Синтаксическая проверка `git diff --check` прошла с предупреждениями Git о
переводах строк. По сообщению исполнителя, отдельный test_release не импортировался в Windows из-за отсутствующего Unix-модуля fcntl; он не входит в указанные 213 тестов. Проверенные файлы и SHA-256 перечислены ниже.

## Выводы по локальной реализации

Месячная проекция проверяет идентичности всех строк доступного ответа до
выбора артикула. Один SKU у разных точных `offer_id`, либо отсутствующий
артикул или SKU в любой строке блокирует расчёт и возвращает ограниченную
диагностику без количественных результатов. Это включает конфликт и пропуск
в строках других товаров: такой ответ намеренно может быть недоступен и для
артикула без собственного наблюдённого конфликта.

Один артикул может иметь несколько SKU; повтор той же пары не удаляет
финансовые строки. Числовой и строковый варианты валидного SKU сопоставляются
точно, артикулы сохраняют регистр и пробелы. Номера строк, не представимые
точно как JavaScript number, отклоняются. Полнота ответа, историческая
принадлежность SKU и аддитивность количеств остаются неподтверждёнными.

Исполнитель исправил найденные в ходе ревизии случаи: отсутствие признака
разрыва синтетической последовательности и повтора номера строки; невалидный
синтетический месяц; позднее истечение deadline во время разбора; неявно
отсутствующее поле фильтра; продолжение после ошибочных часов; изменяемая
ссылка в `snapshot`; конкурентная выдача двух ожидающих запросов; обход
лимитов через подклассы списков и изменение исходных списков во время разбора.
Описания относятся к локальным синтетическим контрпримерам.

Месячная проекция копирует используемые поля до проверки идентичности и
расчёта. Проверка показала, что изменение исходных идентичности и количества
после копирования не меняет результат. Вызывающий обязан не изменять вход во
время самой копии; атомарность ответа источника и независимых запросов этим не
доказана.

Отдельный сканер нескольких `IdentityPage` работает только с синтетическими
страницами. Идентификатор набора и месяц заявляются вызывающим и не доказывают
общий реальный кабинет или происхождение. Порядок страниц и повторы номеров
отображаются отдельно от полноты источника; пагинация месячному API не
приписывается.

`ozon_synthetic_accrual.py` — локальный push/pull state machine, который не
подключён к MCP и не выполняет сеть. Он ограничивает дни, страницы и ID,
останавливается при ошибке и не выполняет автоматический повтор. Совпадения ID
разных дней отмечаются без удаления; счётчик ID относится ко всей синтетической
странице, а не к выбранному SKU. Пустой курсор означает лишь наблюдённый
терминальный курсор, `complete_period` остаётся false, финансовый итог —
`null`. Deadline кооперативный и не прерывает зависший подставной транспорт;
размер памяти уже созданной вызывающим проекции не ограничен этим модулем.
Одновременное изменение входной проекции во время её копирования не является
поддерживаемым сценарием.

Полная финансовая сводка по реальному кабинету, фактические выкупы, возвраты,
выплаты и точность разделения расходов этой проверкой не подтверждены. Linux,
GitHub Actions, production и Claude независимо не проверялись. Изменения не
отправлялись и не развёртывались в рамках этой ревизии.
