# Локальная проверка идентичности месячного отчёта Ozon

Дата: 17 ноября 2026 года. Исходный HEAD: `ebd651e963c95f7c796ff1439bb7498160adfd43`.
На этом этапе использовались только фиктивные ответы, идентификаторы и
подставной транспорт; обращения к реальным API и учётным данным, серверные
действия, push и deploy не выполнялись.

## Воспроизведение и исправление

В `monthly_payload()` значение `rows[2].item.sku` заменили с `99` на `10`.
Один фиктивный SKU оказался у артикулов `0030` и `other`. На исходном HEAD
`ozon_realization_article_month` вернул `observed_delivery_units=2` без
диагностики конфликта. Это относится исключительно к синтетическому ответу.

Теперь все идентификаторы доступного месячного ответа проверяются до отбора
артикула и до расчёта. Один SKU с разными точными `offer_id` блокирует весь
результат, даже когда конфликт находится в строках других артикулов. Пропуск
SKU или артикула в любой строке также блокирует расчёт: по такой строке нельзя
исключить скрытое пересечение. Возвращаются `status=blocked`, причина и
ограниченная диагностика; количества равны `null`, строки и группировки с
финансовыми значениями не выдаются. Обрезка диагностики явно отмечается.

Артикулы сравниваются как точные строки без удаления нулей, пробелов или
изменения регистра. Несколько SKU одного артикула и повтор одной пары
SKU/артикул допускаются; одинаковые финансовые строки не удаляются. Слишком
большие для точного JSON в JavaScript номера строк отклоняются.

До проверки копируются только используемые поля строк. Вызывающий не должен
одновременно менять вход во время самой копии; в штатном worker декодированный
JSON принадлежит одному процессу. Такая копия не доказывает атомарность
источника, полноту отчёта или историческую неизменность связей SKU.

## Синтетические страницы и дни

Месячный метод остаётся одноответным: пагинация API ему не приписывается.
Отдельный типизированный сканер принимает только явно помеченные синтетические
страницы одного идентификатора набора и одного месяца. Он обнаруживает конфликт
между страницами, показывает пропуски порядка и повтор номеров строк, но не
объявляет источник полным или согласованным снимком.

`ozon_synthetic_accrual.py` — локальный state machine без сети и без
подключения к MCP или Docker. С фиктивными страницами он ограничивает дни,
число страниц и ID, разрешает только один ожидаемый запрос, обнаруживает циклы
курсоров и повтор ID внутри дня, останавливается при 429 или другой ошибке и
сохраняет признаки частичного результата. Совпавшие ID разных дней отмечаются,
но не схлопываются. Пустой курсор не доказывает полноту периода; финансовый
итог остаётся `null`. Количество ID относится ко всей синтетической странице,
а не только к выбранному SKU.

Общий deadline кооперативный: вызывающий должен проверять состояние и сам
останавливать свой транспорт. Этот код не может прервать зависший транспорт,
не реализует работу с реальным gate и не готов к использованию в production.
Поздняя страница отбрасывается; поздно полученный фиктивный 429 фиксируется
отдельно. Ограничения внешнего транспорта и памяти уже созданной проекции не
являются проверенными гарантиями этого state machine.

Ни один из результатов не подтверждает корректность фактических начислений,
выкупов, возвратов, выплат или расходов на единицу. Для них по-прежнему нужны
согласованные источники и независимая сверка.

## Проверки

В Windows из каталога `services/email-auth` выполнена команда
`python -B -m unittest -q test_health test_ozon_synthetic_accrual test_ozon_return_events test_ozon_finance_reports test_ozon_posting_candidates test_ozon_article_summary test_ozon_posting_status test_finance_gate test_ozon_details test_ozon_mcp test_external_mcp test_external_mcp_integration test_ozon_response_guard test_provider_payload.ProviderPayloadTests test_provider_deadline`.
Результат: 213 тестов, `OK`; сетевые вызовы заменены тестовыми двойниками.
Отдельный запуск `python -B -m unittest -q test_release` завершился ошибкой
импорта: он требует Unix-модуль `fcntl`, недоступный в текущем
Windows-окружении. Разбор шести изменённых Python-файлов через `ast.parse`
прошёл успешно, `git diff --check` не обнаружил ошибок пробелов. Linux и
Docker в этой локальной проверке недоступны; CI и установку на сервер не
запускали.
