# Независимая проверка частичной сводки Ozon

Дата: 17 ноября 2026 года. Проверены изменения рабочей копии относительно
`52714d3394d268cf9b42725579ee9e6b006d8461`, включая ещё не отслеживаемые Git
файлы. Все проверочные ответы, идентификаторы и ключи были синтетическими;
использовался локальный подставной транспорт.

## Результат и границы

В проверенном локальном сценарии новых блокирующих дефектов именно частичного
контракта не выявлено. Это техническая проверка, а не приёмка полного отчёта.
Полный финансовый отчёт **blocked**: нет подтверждения полноты источника
начислений за период, исторической принадлежности SKU, уникальности и
финансовой аддитивности строк, правил распределения многотоварных расходов,
источников фактических покупательских выкупов и возвратов, а также сверки с
реальным кабинетом. Названия типов начислений могут запрашиваться отдельно;
сама классификация финансовых строк проверкой не подтверждена.

Сверяются прямой ответ по точному `offer_id` и обратный по **наблюдённым** SKU;
несогласованность блокирует запрос начислений. Эти два запроса не доказывают
полноту текущих или исторических SKU и не являются атомарным снимком. Строки
группируются по SKU, типу и валюте; `observed_row_sum` — десятичная сумма
возвращённых наблюдаемых строк, не подтверждённый финансовый итог. Строки без
SKU и чужие SKU не распределяются на выбранный товар. Одинаковые проекции не
удаляются как доказанные дубли. Период фильтруется по дате начисления, а не
по дате заказа или реализации; пустой ответ не доказывает нулевые продажи.

`ozon_posting_candidates` возвращает одну страницу одной схемы, её курсоры и
номера без реквизитов покупателя. Предел входного периода — 90 дней. Повторы
курсоров между вызовами сервер не отслеживает: вызывающий клиент обязан
запомнить посещённые курсоры, остановиться при повторе и отметить выборку
неполной. Повторы номеров между страницами и изменения данных между вызовами
сам инструмент не устраняет. Даже проход всех страниц FBO и FBS не доказывает
полноту начислений за период: дата фильтра отправлений не подтверждена как
дата начисления. Переданные в сводку номера дают только частичный результат.
Пересекающиеся выборки нельзя безусловно складывать.

В синтетических тестах 429 на каждом из трёх последовательных запросов
сохраняет ограничение через gate; тайм-аут проверяется также после подготовки
TLS и до начала запроса. Процессы должны использовать один общий каталог
gate; другие интеграции и отдельные каталоги/хосты им не контролируются.
Неизвестный исход требует предусмотренного отдельного восстановления после
внешней проверки, а не автоматического слепого повтора. Согласованный откат
состояния и внешнего счётчика этим механизмом не обнаруживается.

Реальные кабинеты, ключи, Ozon API, клиент Claude, production, сеть, сборка
контейнера, Linux и GitHub Actions в этой проверке не использовались. Наличие
инструментов в локальном списке MCP не подтверждает их развёртывание или работу
в Claude. `test_release` из-за Linux-модуля `fcntl` на Windows не запускался;
включение нового модуля в Dockerfile и `.dockerignore` проверено статически.

## Независимые проверки

Рабочая папка: `services/email-auth`. Для воспроизведения ниже переменная
`$python` обозначает исполняемый Python из локального Codex runtime. В командах
использованы только синтетические тесты и подставной транспорт.

```powershell
$python = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $python -B -m unittest -q test_ozon_posting_candidates test_ozon_article_summary test_ozon_posting_status test_ozon_details test_ozon_mcp test_external_mcp test_external_mcp_integration test_finance_gate test_provider_deadline
```

Результат: **127 тестов, OK**. После последнего уточнения описания MCP и
соответствующего теста отдельно выполнено:

```powershell
& $python -B -m unittest -q test_ozon_posting_candidates test_ozon_article_summary test_external_mcp test_external_mcp_integration
```

Результат: **49 тестов, OK**. Независимо от имеющихся тестов также выполнены
девять синтетических проверок через Python stdin: точная граница 90 дней;
курсор с Client ID и отказ курсора с тестовым ключом для обоих инструментов;
цикл A→B→A, выявляемый вызывающим клиентом; невалидные/повторённые номера и
пустая страница с признаком продолжения; отсутствие данных покупателя в FBS;
изменение основного SKU до финансового запроса; исключение повторов чужого SKU;
и истечение срока во время подготовки TLS без начала сетевого запроса.
Результат: **9 проверок, OK**. Одноразовый код этих проверок не сохранён;
аналогичные постоянные регрессионные сценарии входят в указанный набор.

`git diff --check` завершился с кодом 0; Git предупредил о возможном изменении
переводов строк при следующей обработке файлов. Команда не проверяет
неотслеживаемые файлы.

При ревизии до финального прогона исполнителю были переданы и исправлены:
непроверенное изменение основного SKU, попадание повторов чужого SKU в группы
товара, отсутствие явного признака непроверенной полноты текущих SKU, начало
запроса после истечения срока во время TLS и ложный отказ курсора, содержащего
Client ID. Для длинных циклов курсоров зафиксирована обязанность клиента;
серверного хранения истории курсоров по-прежнему нет.
