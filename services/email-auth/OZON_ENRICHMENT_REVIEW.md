`codex/ozon-finance-partial-20261117` с базовым HEAD `e0fd85ff81dae77bbfa55e1dce35e4870e6a3168` и

## Проверки

На Windows из каталога `services/email-auth` в stdin `python -B -`
передавалась приведённая ниже программа. Использовался Python из
`%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe`.
Обёртка вызывает `gc.collect()` перед очисткой временных каталогов для
освобождения неиспользуемых SQLite-соединений в тестовом процессе:

```python
import gc, io, sys, tempfile, unittest
original = tempfile.TemporaryDirectory.cleanup
def cleanup(self):
    gc.collect()
    return original(self)
tempfile.TemporaryDirectory.cleanup = cleanup
names = ['test_health','test_ozon_products_enriched','test_ozon_posting_categories',
         'test_ozon_article_summary','test_data_preview','test_connection_check',
         'test_external_mcp_integration','test_finance_gate','test_ozon_details',
         'test_ozon_mcp','test_provider_payload.ProviderPayloadTests','test_provider_deadline',
         'test_ozon_posting_candidates','test_ozon_posting_status','test_ozon_finance_reports',
         'test_ozon_return_events','test_external_mcp','test_external_keys',
         'test_oauth_integration','test_mcp_gateway','test_wb_mcp','independent_ozon_products_probe']
result = unittest.TextTestRunner(stream=io.StringIO(), verbosity=0).run(
    unittest.defaultTestLoader.loadTestsFromNames(names))
print('tests=%d failures=%d errors=%d skipped=%d' %
      (result.testsRun, len(result.failures), len(result.errors), len(result.skipped)))
sys.exit(0 if result.wasSuccessful() else 1)
```

Результат на итоговых байтах: **297 тестов, 0 failures, 0 errors, 0 skipped**.
До последней правки фильтра отдельная одноразовая программа через stdin выполнила
**14 независимых синтетических проверок, OK**; она не сохранена в репозитории.
Проверены межисточниковые
конфликты и отсутствующий владелец SKU, сомнительная числовая форма, лишняя
карточка, область диагностики имени, fallback 401/403 только на втором шаге,
передача 429, неполная валюта и категория, десятичная арифметика, разрез
отправлений, происхождение классификации, фильтрация чужого SKU, отображение
101 SKU и HTML-экранирование, большой ответ и состояние gate после ошибок.
После последней правки отдельно проверены выбранные, чужие и неатрибутированные
одинаковые строки с фильтром и без него, с классификацией и без неё: группы
показывают только выбранные SKU при фильтрации, обе строки выбранного SKU
сохраняются в наблюдаемой сумме, финансовый итог остаётся `null`. Проверка OK.

Ранний прямой прогон 73 тестов на промежуточной версии завершился 39 errors;
показанные ошибки относились к очистке временных SQLite-файлов с WinError 32,
но полный вывод был усечён. Этот запуск не считается успешным. Первый
расширенный прогон с обёрткой дал одну ошибку старого независимого probe:
регистрозависимое ожидание текста размера не совпало с уже существовавшим
сообщением исключения. Исполнитель заменил его проверкой конкретного типа
`ProviderResponseTooLarge`; повторный прогон выше успешен.
`git diff --check` не показал ошибок пробелов; Git вывел предупреждения о
переводах строк.

## Проверенные исправления и границы

- До прикрепления названия и наблюдаемых SKU сравниваются точный артикул и
  product ID; индекс SKU учитывает известные строки страницы и карточек,
  включая отсутствующую карточку и неполного владельца. Выявленные конфликты
  и неподтверждённые формы не приводят к тихому присвоению. Охват SKU,
  согласованность двух запросов и связи за пределами страницы не доказаны.
  Preview показывает наблюдаемые SKU, экранирует текст и отмечает состояние.
- Исправлен синтетически воспроизведённый конфликт: карточка товара A и
  строка товара B без ответа карточки содержали один SKU, но прежний вариант
  присваивал его A. Диагностика исходного списка и покрытие названий карточек
  теперь имеют отдельные области. Проверка подключения в настройках не
  запускает дополнительный запрос карточек.
- Исправлена ложная `incomplete=false` у категории, когда непривязанное
  начисление относилось к другому типу той же категории. Неизвестные валюта,
  типы и расходы без SKU отражаются как ограничения; они не распределяются.
  Категории по отдельным отправлениям сохраняются отдельно, а одинаковые строки
  не удаляются по догадке. Из вложенной диагностики сводки артикула исключены
  повторы чужого SKU; в итоговой версии такой же фильтр применяется к прямой
  сводке `ozon_posting_accruals` и к её разрезу отправлений.
- Суммы — арифметика наблюдаемых строк в разрезе валют, не доказанная выплата,
  прибыль или полный финансовый итог. Категория `returns` обозначает
  связанные с возвратами начисления/услуги, а не сумму возвратов покупателям
  или количество товаров. Текущий справочник типов читается отдельно;
  соответствие его ID прошлым периодам и согласованность снимка не доказаны.
  Сводка артикула указывает источник типов и признаки этих ограничений;
  `include_types=false` отключает классификацию и дополнительный запрос.
- При 401/403 именно дополнительного чтения карточек сохраняется исходная
  страница с явной ошибкой обогащения. 429 и другие ошибки не маскируются как
  успех. Составное финансовое чтение не повторяется целиком автоматически;
  429 и неизвестный исход проверены на синтетическом gate. Gate не
  контролирует товарные вызовы и другие интеграции одного Client ID.
- В синтетическом примере 200 отправлений по 5 типов исходный ответ занимал
  137 912 байт, итоговый compact summary — 328 040 байт при MCP-пределе
  524 288 байт. Это не гарантия для любой допустимой партии: большой ответ
  должен сообщать ошибку без усечения, а партии следует разделять без
  пересечения отправлений.
- Прежний локальный потребитель `daily.ozon_catalog_staging` из другой
  рабочей копии отклонил новый default enriched ответ. На синтетической странице
  старый формат с `include_identity=false` им принят; обогащение названий и
  SKU в этом режиме отключено. Это не проверка production.

Полнота реального периода, фактические выкупы, возвраты и выплаты не
подтверждены. Реальный Ozon, сервер, установка, Linux CI и веб-сессия Claude
независимым ревизором не проверялись. Сведения исполнителя о прежних запросах
находятся в `OZON_PUBLICATION_STATUS.md` и не заменяют эту проверку.
