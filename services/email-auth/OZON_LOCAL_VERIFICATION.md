# Локальная проверка изменений Ozon MCP

Дата: 17 ноября 2026 года. В этой проверке использованы только синтетические
данные и фиктивный gateway. Реальный Seller API и кабинет, сервер, Docker,
Linux и GitHub Actions не проверялись. Изменения в рабочем дереве не означают
установку на сервер.

Команда из каталога `services/email-auth` с локальным Python 3.12:

```text
python -m unittest -q test_ozon_details test_ozon_mcp test_external_mcp test_external_mcp_integration test_ozon_response_guard test_provider_payload.ProviderPayloadTests
```

Результат: 70 тестов прошли. Дополнительную независимую проверку описывает
[OZON_DETAILS_REVIEW.md](OZON_DETAILS_REVIEW.md): она выявила и помогла исправить
неполную обработку сумм и устаревшее ожидание числа инструментов.

Обычный запуск полного `python -m unittest -q` на Windows обнаружил 277 тестов
и завершился 131 ошибкой. В выводе были ошибки очистки временных SQLite-файлов
`WinError 32`; полный набор не считается пройденным. Дополнительный
диагностический запуск полного набора с принудительной сборкой мусора перед
очисткой каждого `TemporaryDirectory` дал 277 тестов, ноль assertion failures и
одну ошибку импорта `fcntl` в Linux-специфичном модуле `test_release`. Это не
обычный прогон CI и не подтверждение Linux или Docker-сборки.

Внешняя проверка схем была выполнена исполнителем по официальной документации;
независимый ревизор сеть не использовал. Указанные в
[OZON_MCP_EVIDENCE.md](OZON_MCP_EVIDENCE.md) ограничения по полному периоду,
выкупам, классификации начислений и последовательности финансовых вызовов
остаются. Публикация, push и развёртывание не выполнялись.
