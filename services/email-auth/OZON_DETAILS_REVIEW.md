# Независимая локальная проверка Ozon MCP

Дата: 17 ноября 2026 года. Проверена локальная доработка вокруг `ozon_product_info`, `ozon_accrual_types` и `ozon_posting_accruals` с синтетическими входами. Это не проверка реального кабинета, доступности Ozon, точности актуальных тарифов или основание для решений о прибыли. Реальные ключи, сеть, push и развёртывание в этой проверке не использовались.

## Результаты

- Строковый `offer_id` сохраняется без числового преобразования. В синтетическом ответе сохранены основной и несколько SKU из разных источников, в том числе идентификатор выше точного диапазона JavaScript; общий SKU двух карточек отмечен конфликтом. Полнота источников и конфликты за пределами ответа не проверены.
- Синтетические начисления суммируются десятично по SKU, типу и валюте. Независимая проверка 400 строк с 50 целыми и 20 дробными цифрами сверила результат с целочисленной арифметикой. Границы периода включительны и относятся к дате начисления; две строки вне периода в итог не вошли.
- При отсутствии суммы, неизвестной валюте, неполученном отправлении или начислении того же типа без SKU итог соответствующей группы в проверенных случаях помечается неполным, а известная сумма остаётся частичной. Неатрибутированные начисления не распределяются между товарами. Проверка содержит положительные и отрицательные синтетические суммы.
- Фиктивное эхо ключа в ответе провайдера отклонено. Статически проверены фиксированные адреса и POST-запросы на чтение, маршрутизация MCP и включение нового файла в Dockerfile и `.dockerignore`.

## Найденные и исправленные при ревизии дефекты

Первоначально отсутствующее начисление отделялось в группу неизвестной валюты, а сумма той же пары SKU/типа в RUB выводилась как полный `total`. Даже при известной валюте отсутствующей суммы её валюта терялась. Исполнитель изменил обработку: известная валюта сохраняется, неопределённость валюты и пропуски учитываются при обозначении итогов. Самостоятельные повторные синтетические проверки прошли.

Интеграционный тест списка MCP ожидал девять инструментов и падал с результатом `12 != 9` после добавления трёх. Исполнитель заменил ожидание проверкой точного набора имён; повторный прогон включал этот тест и прошёл.

## Выполненные проверки

Из каталога `services/email-auth` выполнена команда:

```text
python -B -m unittest -q test_ozon_details test_ozon_mcp test_ozon_response_guard test_external_mcp test_external_mcp_integration
```

Результат: **59 тестов прошли** на Windows, Python 3.12, с установленной локально `cryptography 50.0.2`. Дополнительно выполнено **9 независимых тестов в памяти** на сохранение нескольких SKU и конфликта, точность десятичных сумм, обе границы периода, неизвестные сумму и валюту, отсутствие отправления, строку без SKU и эхо фиктивного ключа. Все девять прошли. Ещё один независимый in-memory сценарий вызвал настоящий `Portal` из двух потоков с фиктивными аутентификацией и gateway: оба вызова финансового инструмента одновременно вошли в gateway; сетевых вызовов не было.

Отдельная попытка `python -B -m unittest -q test_release.PortalRuntimeContractTests` на Windows завершилась ошибкой импорта отсутствующего модуля `fcntl`; этот тест не засчитан как успешный. Docker-сборка, Linux и GitHub Actions не запускались. `git diff --check` не сообщил об ошибках пробелов; имелись предупреждения Git о преобразовании переводов строк.

## Оставшиеся ограничения

- Полная сводка по артикулу, фактические выкупы, возвраты и выплата на единицу **не реализованы и не подтверждены**. Инструмент работает только по переданным отправлениям; полную совокупность отправлений за период он не получает. Историческая полнота SKU и правила распределения расходов без SKU не подтверждены. Строка начисления не равна выкупу или прибыли.
- Финансовые запросы не сериализованы общим межпроцессным механизмом по Client ID. Синтетическая проверка подтвердила одновременное выполнение двух запросов в одном процессе; внешние интеграции с тем же Client ID и фактическое поведение Ozon не проверялись. Вопрос необходимо решить перед заявлением о последовательном доступе.
- `inputSchema` описывает поля, но не выражает все взаимные ограничения: для `ozon_product_info` требуется ровно один вид идентификаторов, а фильтр `skus` для начислений допустим при `view=summary`; также даты задаются парой. Runtime такие некорректные комбинации отклоняет. Клиент, который руководствуется только схемой, может получить `invalid_arguments`.
- Официальные схемы внешних методов в рамках этой независимой проверки по сети не проверялись. Ссылки и сведения исполнителя собраны в `OZON_MCP_EVIDENCE.md`; синтетические фикстуры не подтверждают реальный формат или полноту ответов, права ключа и ограничения конкретного кабинета.
