# Отчёты MCP для Ozon и Wildberries

Для дневного ряда заказов WB передайте в `wb_orders` артикул, даты, `group_by=day` и `limit=100`. В поле `ordered_units` входят отменённые заказы, их количество отдельно показано в `cancelled_units`. Нули появляются только за дни, полностью прочитанные из источника. Недельная группировка начинается в понедельник.

При ограничении частоты `wb_orders` возвращает уже собранные строки с `complete=false`. Когда у части заказов отсутствует признак отмены, `cancelled_units` остаётся пустым. Отдельно указаны число подтверждённых отмен и количество штук с неизвестным статусом. У `wb_region_sales` границы календарного дня относятся к московскому времени, а дата события — к последнему изменению статуса заказа.

Недельная строка содержит границы запрошенной части недели и число покрытых дней. До полного покрытия количество найденных штук доступно в `observed_ordered_units`, а итог за интервал остаётся пустым.

`sales_drop_check` запрашивает основные метрики заказов Ozon за оба периода вместе, если они укладываются в 90 дней. Просмотры и корзины требуют Premium Plus. В ответ попадают значения за совпадающие SKU и даты. Данные о рекламе, отзывах и истории остатков сопровождаются сведениями о доступности.

`ozon_delivery_time` возвращает локальность продаж по товару или кластеру. Без этих фильтров доступна общая доля локальных продаж кабинета. Поле длительности доставки остаётся пустым, поскольку отчёт Ozon содержит только показатели локальности.

В кабинете можно сохранить общий токен WB и отдельные токены категорий. Инструмент `mcp_health` возвращает время последнего обращения с текущим набором ключей. Для активной проверки одного метода передайте его имя в `tool_name` и обычные аргументы в `probe_arguments`. Срок действия WB берётся из самого токена. Доступ к конкретному методу подтверждает ответ площадки.

## Сопоставление и расчёты

- `article_map` сверяет ручную пару артикулов с обоими каталогами и сохраняет в ответе все SKU. Таблица соответствий хранится на сервере рядом с каталогом финансовых блокировок в приватном файле `supply-articles.json`.
- `supply_plan` рассчитывает потребность за срок доставки и интервал между поставками с учётом страхового запаса. При явном `bulk_order_min_units` применяется заданный порог. По умолчанию для выброса нужны не менее 10 штук, четырёхкратный размер медианного заказа и выборка хотя бы из пяти заказанных позиций. Одиночный снимок нулевого остатка оставляет доступность дня неизвестной. Источники, календарные количества и покрытие истории выводятся отдельно.
- `unit_economics` использует валовое количество проданных штук как знаменатель. В WB `forPay` уже учитывает вознаграждение за продажу. У Ozon поле `total` относится к части месячного отчёта реализации. Начисления по отправлениям группируются по SKU, типу и валюте. Отчёт сохраняет знак возвратов и раскрывает пропуски в составе расходов.
- `sales_drop_check` сравнивает две пары дат. Уровень конверсии рассчитывается из суммарных просмотров и корзин. Сравнение содержит покрытие остатков, рекламных отчётов и выборки отзывов.
- Для состава поставок за период передайте `article` в `wb_supplies` или `ozon_supply_orders`. При статусе `pending` следующий вызов продолжит сохранённый обход. Даты означают создание поставки WB и начало таймслота Ozon.

## История и доступность источников

В региональном отчёте WB одна запись соответствует одной заказанной единице в её текущем статусе. Если WB вернул меньше запрошенного лимита и оставил `snapshotTime` пустым, это последняя страница. Время в `data_as_of` тогда означает получение ответа. Если страница заполнена до лимита и время снимка отсутствует, MCP возвращает прочитанные записи с `complete=false`. Переход на следующую страницу требует согласованного снимка.

Для ленты заказов WB интервал между обращениями действует на кабинет. При замене ключа новая версия переносит остаток паузы в запись, которую читает и предыдущая версия. При первом появлении незнакомого ключа перенос старых непрозрачных записей может установить консервативную локальную паузу до трёх часов. Если после отката на `a51e141` впервые сохранить совершенно новый токен, эта старая версия начинает собственный отсчёт после успешного ответа. Полученный HTTP 429 и прерванный запрос защищает отдельное ограничение на метод и кабинет, которое обе версии проверяют при любом токене.

При чтении архива Ozon по артикулу поле `unresolved_article_rows` показывает число строк, для которых архив сохранил SKU, но не смог подтвердить принадлежность к артикулу. Такая выборка имеет `complete=false`. По точному SKU сохраняются подтверждённые значения, включая нулевые заказы.

Если при сравнении двух периодов каталог одной площадки недоступен, `sales_drop_check` возвращает данные площадки с подтверждённым точным артикулом. В `unavailable_marketplaces` указываются источник ограничения, HTTP-код и срок повтора, когда они известны.

Таймер `wbozon-market-archive.timer` вызывает закрытую операцию обычного API портала каждые 15 минут. За один проход обновляется одна страница каждого доступного набора. Покрытие завершённого дня фиксируется после окончания пагинации. Архив сохраняется при откате. Параметр `archive=true` у заказов, продаж, финансов WB и дневной аналитики Ozon показывает сохранённые даты и пробелы. Исходные отчёты WB за последние два календарных дня предварительны.

Монитор схем запускается от системного пользователя `wbozon-schema`. При установке поместите `tools/native-release/wbozon-schema.sysusers.conf` в `/etc/sysusers.d/` и выполните `systemd-sysusers /etc/sysusers.d/wbozon-schema.sysusers.conf` до запуска `wbozon-market-updates.service`. Приватное состояние хранится в `/var/lib/wbozon-market-updates`. Портал читает публичные статусы из `/run/wbozon-market-updates/status.json`.

У Ozon `ozon_delivery_time` возвращает локальность и количество доставок по кластеру. В опубликованной схеме отчёта отсутствует фактическое время доставки покупателю. У WB `wb_region_sales` использует ленту текущих статусов за 31 день, а дневная история воронки доступна за последнюю неделю. Доступ к поисковым фразам требует «Джем». Отчёты и временные отключения проверяются по официальным публикациям площадок.
