# Планирование производства

`production.planning` — локальные функции для расчётов по разделу 9.2 ТЗ. Это предложения технологу: модуль не отправляет задания на печать, не проверяет доступную мощность физических принтеров и не заменяет утверждение владельца первой партии. Все входные сведения, их источники и дату наблюдения должен передавать и хранить вызывающий код.

- `first_batch(daily_sales)` — прогноз на 14 дней, округлённый вверх до штук, в пределах 10–30; первая партия требует решения владельца.
- `replenishment(daily_sales, lead_time_days, stock, in_transit)` — точка заказа и размер дозаказа. Условие заказа — остаток **строго ниже** точки заказа, как в ТЗ; количество округляется вверх и не может быть отрицательным. Товар в пути учитывается при определении количества. Предложение дозаказа следует применять только при `below_reorder_point: True`.
- `allocate_capacity(printers, planning_days, products)` — расчёт мощности по формуле `количество принтеров × 24 × 0,7 × число дней` и распределение целых штук в порядке убывания прибыли за час печати. В каждом товаре нужны `sku`, `quantity`, `print_hours`, `profit_per_hour`. Часы, которые не уместились в план, возвращаются в `unplanned_hours`; значение может быть больше чистой разницы мощности из-за неделимости изделий. Реальную доступность, совместимость принтеров и разрешение на выполнение следует проверить отдельно. Товары с отрицательной прибылью тоже могут войти в распределение; вызывающий код должен заранее исключить товары, не прошедшие экономическую проверку.

Пример с условными числами:

```python
from production import first_batch, replenishment, allocate_capacity
print(first_batch("1.2"))
print(replenishment("1.2", "5", 10, 2))
print(allocate_capacity(1, 1, [{"sku": "example", "quantity": 4,
                               "print_hours": "5", "profit_per_hour": "120"}]))
```

Данные примера не относятся к производству владельца. Параметры продаж, оборудование, остатки и прибыль должны быть получены из подтверждённых источников; недостающие значения не подставляются автоматически.

Арифметика при распределении выполняется точно, без округления мощности в пользу планируемого изделия. Для защиты от чрезмерных вычислений входное число ограничено 1000 значащими цифрами и десятичным показателем от −1000 до 1000.
