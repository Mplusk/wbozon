# Локальный переход кандидата

Команда пытается перевести уже сохранённую запись на следующую стадию, используя проверки `pipeline.advance`. Она читает последнюю версию под блокировкой записи SQLite, проверяет ожидаемый номер версии и добавляет новую версию в той же транзакции. При несоответствии версии (`stale`) или невыполненных условиях (`blocked`) изменений не делает. Два одновременных запроса для одной версии не могут оба выполнить переход.

```bash
python3 -m scout.advance \
  --db /путь/к/закрытой-базе.sqlite3 \
  --candidate-id demo-001 \
  --expected-revision 1 \
  --source https://example.org/model \
  --observed-at 2026-11-12T12:00:00+03:00
```

Используйте действительные идентификатор и номер последней просмотренной версии; URL и дата в примере условны. `source` должен ссылаться на материалы, подтверждающие состояние паспорта на указанное время; при нескольких источниках укажите ссылку на пакет с источниками. Секреты в аргументы передавать нельзя. Номер новой версии и стадия выводятся при успехе. `0` означает локальный переход, `2` — блокировку или устаревшую версию, `1` — ошибку ввода или хранения.

Ворота владельца эта команда никогда не переводит, даже если в паспорте записаны утверждения об одобрении. Для них используется доверенный серверный переход `GateStore.transition_approved`; см. `gates/README.md`. Это проверка **записанных полей**, а не авторизация. Ссылки, сведения о правах, подписи владельца, подтверждение Telegram и отчёты ревизора не удостоверяются автоматически. Стадия не является разрешением на печать, публикацию или изменение кабинета; выполнять такие действия через этот инструмент невозможно. Защищённый шлюз и подтверждения ещё предстоит реализовать. При прямом доступе к базе пользователь может изменить данные; блокировка предотвращает гонку штатных записей, а не подмену SQLite.
