# Manual offline local CI (not a registered runner)

One reproducible command executes the reviewed59 portal tests and46 native CD
tests in a new temporary Python3.12 venv. It does not contact GitHub, SMTP, seller
APIs, Docker or systemd; no real production credentials/data are supplied. Inputs
are manifest-pinned copies, never live production release paths. No git actions,
runner installation, persistent credentials or automatic deployment are included.

## Prerequisites and command

Linux CPython3.12 with venv/ensurepip already available; reviewed portal bundle with
complete wheelhouse and hash-locked requirements. The existing wheelhouse targets
x86_64/glibc>=2.34. Unsupported platform/install fails; no source-build/network fallback.
Trust/review these files and hash pins before execution: hashes prove identity, not
that arbitrary source or wheels are safe. Do not generate a new expected hash from
untrusted input merely to make verification pass.

From this prepared cloud workspace:

```
python3 /workspace/shared/local-ci/run_local_ci.py \
  --portal-bundle /workspace/shared/portal-native \
  --portal-manifest-sha256 7d03a2e8e78c8dd98a791650c55e725b1ead586860d5d511fe8736ff5c091ff8 \
  --native-dir /workspace/shared/native-cd \
  --native-manifest /workspace/shared/local-ci/NATIVE_SHA256SUMS \
  --native-manifest-sha256 75e32f89f5eed9a2ee34621d749014d0433767836b668211203b3e529ad9c151
```

Review/adjust only local input paths when materializing on another machine. Native
manifest pins the two reviewed PR4 source/test files; portal manifest pins service,
tests and wheels. Script copies only manifest-listed files into temp workspace and rehashes EACH
copied file before running any venv/pip/test command. Manifest bytes are parsed from
the same byte buffer whose pin was checked. It
installs via --isolated --no-index --only-binary --require-hashes, checks exact discovered/executed test
counts with no skips/expected-failures and revalidates sources afterwards. Temporary DBs/secrets are generated by
test fixtures, then removed with the temporary workspace. Original inputs unchanged.
Output JSON is manual CI evidence with input hashes, counts and limits. Exit0 means
both suites passed; missing tests, changed files/dependencies or errors fail closed.
Redirect output to a LOCAL report if desired. Do not paste production secrets into
CLI flags/environment. Minimal child environment excludes proxies/auth/PYTHONPATH.

Self-tests: `cd /workspace/shared/local-ci && python3 -m unittest -v test_local_ci`.
They verify manifest tampering/symlinks/traversal, environment isolation, denial of
socket/DNS/process/shell operations, expected test count, timeout and system-path input
rejection. Real offline end-to-end output is recorded in RESULT.json.

## Safety boundaries and limitations

- No real HTTP smoke: even loopback sockets are forbidden during these tests.
  Auth, CSRF, encrypted storage and read gateway are exercised in process with
  synthetic data and mocked external interactions. Systemd/Docker calls are mocked.
- Python audit hooks reject socket events in pip installation and tests; tests also
  reject subprocess.Popen/os.system/os.exec/os.posix_spawn. This is NOT an OS network
  sandbox and is NOT safe execution of hostile native extensions or arbitrary code.
  Native C code or deliberately malicious packages can bypass Python auditing.
  Only independently reviewed pinned sources/wheels are acceptable. No assurance
  of protection against a malicious repository contributor is claimed.
- Venv creation uses standard ensurepip without network; all children receive
  minimal environment. Commands have180s bounds. No global packages are installed.
- Host systemd sandbox, production ownership, credentials permissions, deployment,
  bootstrap, actual SMTP/seller access and schema migrations are NOT validated here.
- Windows-native is unsupported (fcntl/fork); use approved Linux environment.
- GitHub billing block remains. A local PASS is not a GitHub check, does not change
  branch protection and does not authorize merge/deployment or financial changes.

All work is local. Changes are held for the owner's approximately hourly commit/push
cadence, not pushed after every edit; no scheduled publish or unattended run exists.
